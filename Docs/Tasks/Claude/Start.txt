Создай прототип WPF-приложения (.NET 8, C#) — дашборд для визуализации мультиагентной системы (агенты выполняют разные задачи, не трейдинг). Сейчас нужен только UI на моковых данных, без реальной интеграции с бэкендом — архитектура должна позволять потом просто подменить источник данных.

СТЕК И ПАТТЕРНЫ
- .NET 8, WPF, MVVM (CommunityToolkit.Mvvm: [ObservableProperty], [RelayCommand])
- Тёмная тема, чистый минималистичный стиль (как у dev-инструментов: VS Code / трейдинг-терминалы), без Material/дефолтных WPF-контролов "из коробки" — свои стили под Border/Button/ItemsControl
- Разбить на проекты или хотя бы папки: Models, ViewModels, Views, Services (Services пока с одной заглушкой MockAgentDataService)

ЛЭЙАУТ ГЛАВНОГО ОКНА (Grid, 2 строки x 2 колонки)
1. Левая большая область — список агентов в виде карточек (ItemsControl + UniformGrid или WrapPanel):
   - имя агента, роль (Developer/Researcher/Universal и т.п. — сделай enum AgentRole с 4-5 значениями)
   - статус с цветовым индикатором: Idle (серый), Thinking (жёлтый, пульсирующая анимация), WaitingApproval (оранжевый), Working (зелёный), Error (красный)
   - краткое описание текущей задачи (1 строка, обрезать с "...")
   - клик по карточке — выделяет агента (рамка/подсветка) и обновляет правую панель
2. Правая узкая панель — детали выбранного агента:
   - имя, роль, модель (mock-строка типа "Hermes-4-70B via Nous Portal")
   - текущая задача (полный текст)
   - мини-история последних 5-10 сообщений/действий этого агента (список с временными метками)
3. Нижняя полоса на всю ширину — общая лента событий (live log) по всем агентам:
   - таблица/список: время, агент (цветной тег), тип события (tool_call/message/error), текст
   - фильтр сверху: dropdown "все агенты" / конкретный агент

ДАННЫЕ
- Создай Models: AgentModel (Id, Name, Role, Status, CurrentTask, Model), AgentEventModel (Timestamp, AgentId, EventType, Text)
- MockAgentDataService: генерирует 5-6 агентов с разными статусами и ~20 событий в ленте, плюс DispatcherTimer, который раз в 2-3 секунды меняет статус случайного агента и добавляет новое событие в ленту — чтобы сразу видно было, как дашборд выглядит "живым"
- MainViewModel: ObservableCollection<AgentViewModel>, ObservableCollection<AgentEventViewModel>, SelectedAgent, подписка на MockAgentDataService

ЧТО НЕ НУЖНО СЕЙЧАС
- Не делай реальных HTTP-запросов, SSH, Tailscale — только заглушка с интерфейсом IAgentDataService, чтобы потом можно было подменить на реальную реализацию
- Не делай граф связей между агентами (это следующая итерация, если карточек будет мало)

Результат: рабочее WPF-приложение, которое запускается и показывает "живой" дашборд на моковых данных.
